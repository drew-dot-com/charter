# Charter v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Charter v1, a compute marketplace on TOON mainnet: a host program on Drew's home machine, a hosted storefront and x402 door that lets anyone with a browser wallet rent, a tenant CLI that Edison uses, and one real paid lease you can verify on chain.

**Architecture:** charter-host runs next to a `toon` 0.3.0 node and exposes three HTTP listeners (open, tick, status) that the node puts behind three priced TOON apps. Tenants pay those routes per packet. The door runs on Drew's Hetzner node: a browser renter pays it per interval over x402, and it pays the host the same interval over TOON from its own channel. Offers are signed Nostr events of a Charter-owned kind, written to Drew's relay.

**Tech Stack:** TypeScript, Node 22+, ESM, `node --test` with tsx, express 5, `@x402/express` / `@x402/fetch` / `@x402/evm` (as pinned in LADING), `@toon-protocol/client` ^4.1.0, `nostr-tools`, viem, esbuild for the browser bundle, Docker (Playwright image for the job), `toon` CLI 0.3.0.

**Spec:** `docs/superpowers/specs/2026-10-16-charter-design.md`

## Global Constraints

- The repo is `drew-dot-com/charter`, MIT, at `~/src/TOON/charter`. Its stack matches LADING (`~/src/TOON/lading`), so copy its tsconfig, test script, and x402 and ToonClient setup patterns. It is Drew's own code.
- Read **nothing** from `toon-protocol/provider`, `toon-protocol/console`, or the `toon-protocol/TOON_Network` spec, and do not use kinds 10432, 30432, or 10433.
- No em dashes in any shipped string, README, page, or commit message.
- Mainnet only. No devnet or testnet anywhere.
- Never print or commit secrets. Passphrases and keys come from files named in env vars. When you dump env, filter `JWK|SECRET|PRIVATE|KEY`.
- Copy rules: say "accountless" and "hidden host". Never say "anonymous payments", "any token", or that Charter has outside users.
- Amounts are `bigint` in USDC micro-units (6 decimals): `1000n` is 0.001 USDC.
- v1 values:

  | setting | value |
  | --- | --- |
  | `intervalSeconds` | 30 |
  | `tickPrice` | 5000n |
  | `openPrice` | 1000n |
  | `statusPrice` | 100n (Task 1 confirms the minimum) |
  | grace | first tick 90 s from container create (`firstTickGraceSeconds` in the offer), later ticks 10 s (F-C3) |
  | boot timeout | 120 s |
  | door fee | 0 |
  | offer kind | 31390, tag `["L","charter"]` |
  | offer lifetime | 30 min, republished every 10 min |
  | output part size | 48 KiB |
  | job limits | 1 CPU, 1 GiB, 256 pids |

- Any step that spends real money or funds a wallet stops for Drew's go-ahead in chat.

## Review Focus

1. **A tenant pays the cheap route but asks for an expensive action**, for example sending a `/tick` body to the `charter-open` route. Expected: each listener serves only its own action. Test in Task 6.
2. **A tick packet arrives twice** because of a retry, and was paid both times. Expected: the interval counts once, the answer says `duplicate: true`, and the lease is not corrupted. Test in Tasks 2 and 6.
3. **charter-host restarts mid-lease.** Expected: leases reload from disk, and a lease whose container is gone is closed `host_restart`, not left running forever. Test in Task 6.
4. **The renter closes the browser tab mid-lease.** Expected: the host stops at the window, the door shows `closed: missed_tick`, and the renter paid only for intervals they signed. Test in Task 8.
5. **x402 settlement fails after the door already paid the host.** Expected: the renter is not charged, the door records the loss in its ledger, and it stops ticking that lease. Test in Task 8.

### Task 8: The door: x402 in, TOON out

**Files:**
- Create: `src/door/server.ts`, `src/door/ledger.ts`, `src/door/main.ts`

**Interfaces:**
- Consumes: `hostApi` and `fetchOffers` (Task 7), and `ToonClientPayer` (Task 4).
- `src/door/ledger.ts`: `DoorLedger` (JSON file, atomic writes). It records each door lease `{ leaseId, offerId, payer?, ticksPaidByRenter, ticksPaidToHost, losses: Micro }`.
- `src/door/server.ts`: `doorApp(deps: { offers: () => Promise<Offer[]>; api: (o: Offer) => HostApi; ledger; x402: { payTo: string; network: 'eip155:8453'; facilitatorUrl: string } | 'free-for-tests' })`
  - `GET /v1/offers` is free and CORS-open, with offers cached 60 s.
  - `POST /v1/leases`, body `{ offerId, urls: string[] }`. It is free and rate-limited to 10 per hour per IP. It calls `api.open` and answers `{ leaseId, state }`.
  - `POST /v1/leases/:id/ticks`, body `{ index }`, is x402 `exact` priced at `tickPrice` (door fee 0), with USDC on Base.
    - Once the payment verifies, it calls `api.tick`. On 200 it answers 200, and the middleware settles after the 2xx (LADING's order).
